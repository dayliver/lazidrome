# 모바일 UI 개선 계획

라우트 23개와 공통 편집 창, 검색, 재생 UI를 소스 기준으로 조사했다. 아래에서 확인한 배치와 실제 터치·키보드 검증 항목을 구분한다. 모바일 실기기 검증은 구현 단계에서 진행한다.

## 1차 — 플레이리스트 등록과 음원 가져오기

플레이리스트 편집·선택 창, 스마트 믹스 조건 세로 배치, 곡 이동 버튼과 가져오기 입력 배치를 구현했다. 아래 사용 흐름은 모바일 브라우저와 실기기에서 확인해야 한다.

1. `AppEditShell`을 모바일에서 화면 전체를 쓰는 편집 창으로 변경한다. 헤더와 저장 영역 사이에 본문 스크롤을 두고, 주소창·키보드 변화와 안전 영역을 반영한다. 기본 정보·곡·커버 탭은 현재 위치와 이동 가능한 탭이 드러나게 배치한다. 키보드가 열린 상태에서 입력칸과 자동완성 결과에 접근할 수 있어야 한다.
2. `PlaylistBasicInfoTab`의 이름과 설명을 세로 배치한다. 스마트 믹스는 지금 조건마다 폭 160px 선택 상자 두 개, 값 입력, 삭제 버튼이 한 줄에 있다. 모바일에서는 조건별 카드 안에 필드·연산자·값을 각각 한 줄로 놓고, 조합 방식·정렬·최대 곡 수도 좁은 폭에서 세로로 배치한다.
3. `PlaylistTracksTab`은 곡 검색 결과와 선택 목록에 입력·조작 공간을 확보한다. 곡 이동은 드래그 핸들과 위·아래 이동 조작을 제공한다. 트랙 목록과 상세 화면에서 사용하는 `PlaylistSelectModal`도 검색 키보드가 열린 상태에서 결과를 선택할 수 있게 하고, 추가 동작 표시를 터치 화면에서 항상 보여준다.
4. `/import`와 `/upload`는 현재 작업 트리의 곡별 카드와 URL 세로 배치를 기준으로 이어간다. 일괄 메타데이터 입력, 곡 선택과 페이지 이동, 자동완성, 업로드 진행·실패·완료, 긴 파일명을 확인한다. 좁은 화면에서도 제출 버튼에 접근할 수 있게 배치한다.

일반 목록 생성 → 곡 추가·순서 이동 → 저장·재진입, 스마트 믹스 생성 → 조건 여러 개 설정·삭제 → 저장·재편집, 곡 메뉴 → 기존 목록에 추가를 각각 검증한다. 가져오기는 URL과 로컬 파일 양쪽에서 선택, 메타데이터 수정, 제출까지 확인한다.

## 2차 — 메타데이터·태그와 관리 화면

- `MetadataEditDialog`와 `TagEditDialog`에 1차 편집 창 배치를 적용한다. 앨범 곡 행의 디스크·트랙 번호는 제목 및 커버와 별도 줄로 배치한다. 아티스트 역할, 외부 메타데이터, 커버 편집 탭의 검색과 버튼도 확인한다.
- 앨범·태그 생성, 태그 일괄 편집, 곡 오디오 교체 창에서 긴 파일명, 검색 결과, 확인·취소 버튼을 확인하고 좁은 폭에서 줄바꿈을 허용한다.
- `/files`는 파일명과 기본 정보를 우선하는 모바일 목록으로 바꾸고 작업을 메뉴로 모은다. 경로 탐색과 긴 파일명을 함께 확인한다.
- `/settings`는 서버 입력·접속 버튼과 재생 기기 조작을 세로 배치하거나 줄바꿈한다. `/admin`은 항목 이름과 작업을 별도 줄로 배치하고, 하단 저장 영역이 플레이어와 겹치지 않도록 한다.
- `/stats` 기간 선택은 가용 폭을 사용하게 하고 시간대 차트는 모바일에서 주요 값과 시간 구간을 읽을 수 있게 조정한다.

## 3차 — 탐색과 재생 화면 정리

| 화면 | 확인 사항과 수정 방향 |
| --- | --- |
| `/` | 가로 카드 스트립은 의도된 제스처다. 세로 페이지 스크롤, 카드 끝 노출, 긴 제목을 확인한다. |
| `/tracks` | 기존 모바일 행과 벌크 작업을 사용한다. 필터와 선택 도구 및 곡 메뉴의 터치 영역을 확인한다. |
| `/albums`, `/artists`, `/tags` | 기존 반응형 그리드를 사용한다. 아티스트 분류 선택 폭과 그리드의 긴 이름, 헤더 액션 줄바꿈을 조정한다. |
| `/playlists` | 목록에 모바일 전용 행이 있다. 더보기 버튼의 터치 영역과 생성 버튼·제목 배치를 개선한다. 생성과 편집은 1차 범위다. |
| `/album/:id`, `/artist/:id`, `/track/:id`, `/tags/:name`, `/playlist/:id` | 상세 헤더의 제목과 공유·편집·재생 버튼을 줄바꿈한다. 공통 곡 목록의 메뉴를 확인하고 곡 상세의 소속 플레이리스트 표와 상세 화면의 아티스트 표는 좁은 폭에서 필요한 정보부터 보여준다. |
| `/history` | 시간에 고정 폭을 주는 행에서 곡 제목이 짧아진다. 시간과 재생 길이를 보조 줄에 배치한다. |
| `/charts`, `/charts/weekly`, `/charts/monthly`, `/charts/alltime` | 기존 모바일 구조에서 차트 탐색·기간 선택·긴 곡명·순위 표시를 확인한다. |
| `/download` | `/import`로 이동하는 별칭이다. 기존 `/import?tab=files` 경로의 `/upload` 이동도 확인한다. |
| 전역 탐색·검색·재생 | 모바일 헤더, 햄버거 메뉴, 검색, 미니·전체 플레이어, 재생 대기열 사이의 겹침과 초점 복귀를 확인한다. `App.vue`의 고정 뷰포트 높이가 주소창이나 키보드 변화에 영향을 주는지 점검한다. |

## 완료 기준

- 1024px 미만에서 같은 폼 영역의 입력칸·선택 상자·텍스트 영역은 한 줄에 하나씩 배치한다. 768px과 가로 방향도 확인한다.

- 320, 360, 390, 768px 및 데스크톱에서 확인한다. 화면 전체가 옆으로 밀리는 경우를 없애고 홈 카드 스트립 등 의도된 영역의 제스처를 보존한다.
- 모바일 Safari, Android Chrome과 Android 앱에서 키보드 열기·닫기, 세로·가로 회전, 안전 영역, 모달 닫은 뒤 초점 복귀를 확인한다.
- 주요 터치 조작은 44px 내외의 영역을 확보한다. 한국어·영어의 긴 라벨, 긴 음원명, 빈 결과와 오류 상태를 확인한다.
- 단계별로 프런트엔드 빌드와 변경한 흐름을 확인한다. 공통 편집 창을 바꿀 때는 플레이리스트·메타데이터·태그의 저장과 취소, 데스크톱 표시를 함께 검증한다.
